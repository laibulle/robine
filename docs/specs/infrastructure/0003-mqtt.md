# 0003 — Intégration MQTT

## Objectif

Connecter Robine à un broker MQTT local afin d'intégrer des appareils, capteurs, passerelles et firmwares ouverts sans lier le modèle métier aux topics ou payloads de chaque fabricant.

MQTT est une intégration de transport, pas une base de données ni un bus interne de Robine. Le journal SQLite demeure la source de vérité ; le broker est une source d'événements externe et potentiellement non fiable.

## Portée V1

`robine-protocol-mqtt` se connecte à un broker existant. Robine ne distribue ni n'administre un broker MQTT en V1. L'installation guidée accepte un broker local ou LAN configuré par l'administrateur.

Le client prend en charge MQTT 3.1.1 comme socle d'interopérabilité et MQTT 5 lorsque le broker le négocie. TLS, authentification par mot de passe et authentification par certificat client sont supportés. Les secrets restent dans le magasin de secrets, jamais dans SQLite, une sauvegarde standard ou un diagnostic.

Les profils de capacité V1 sont `light`, `switch`, `sensor`, `binary-sensor`, `cover` et `climate`. Chaque profil est traduit vers les capacités canoniques Robine ; un message MQTT ne crée pas librement une propriété ou commande non validée.

## Configuration et découverte

Un adaptateur MQTT est configuré depuis les apps Apple ou la console de secours : adresse, port, TLS/CA, authentification, préfixes de souscription, politique de découverte et limites de débit. Aucun fichier YAML n'est requis ou interprété.

Trois modes de découverte existent :

| Mode | Usage | Règle |
|---|---|---|
| Robine Discovery | nouveau matériel et intégrations Robine | payload JSON versionné sous `robine/v1/discovery/...` |
| Mapping guidé | appareil MQTT propriétaire ou ancien | formulaire qui associe topics, types, unités et commandes validés |
| Home Assistant Discovery | compatibilité avec l'écosystème existant | import d'un sous-ensemble JSON, sans template ni expression libre |

L'import Home Assistant prend en charge les annonces par appareil pour les profils V1. Les `value_template`, scripts, commandes shell et propriétés inconnues sont refusés explicitement. Les topics et identifiants annoncés sont des adresses d'infrastructure ; Robine génère ses propres `DeviceId` et `EntityId` opaques.

Un appareil n'est créé ou mis à jour qu'après validation d'un identifiant stable d'origine et d'un descripteur de capacité. Une redécouverte ne remplace ni son nom Robine ni son classement en pièce sans accord explicite.

## État, disponibilité et commandes

L'adaptateur souscrit aux topics de découverte, d'état, de disponibilité et d'événement de chaque appareil enregistré. Les messages retenus sont admis comme état initial seulement après validation et restent identifiés comme rapportés par MQTT.

La disponibilité utilise, dans l'ordre, le topic explicite de disponibilité, le Last Will and Testament quand il est fourni, puis la santé de l'adaptateur. L'absence d'un message n'est jamais interprétée comme un appareil allumé, éteint ou supprimé.

Une commande Robine est validée par capacité puis publiée sur le topic configuré. Le `PUBACK` ou succès d'écriture réseau confirme seulement le transport. Une confirmation `:reported` attend un message d'état correspondant ; les appareils qui ne peuvent pas rapporter leur état ne promettent jamais cette confirmation.

Les commandes possèdent une clé d'idempotence Robine. Lorsque le format du profil permet un champ de corrélation, l'adaptateur le propage ; sinon il déduplique localement par `(entité, propriété, valeur, fenêtre de temps)` sans réémettre une même intention.

## Fiabilité et pression de retour

- Les payloads, topics et JSON ont des tailles maximales configurables avant désérialisation.
- Les messages entrants sont normalisés dans une file bornée ; une surcharge est mesurée et entraîne une dégradation de l'adaptateur plutôt qu'une consommation mémoire illimitée.
- L'ordre MQTT n'est supposé que dans un topic et une connexion donnés. Une `StateVersion` Robine protège la projection contre les doublons et les retards.
- La reconnexion applique un backoff avec gigue, réinstalle les souscriptions puis demande la republication de découverte par le message de naissance configuré.
- Les publications de commande sont limitées par appareil et par adaptateur ; les mises à jour concurrentes de même propriété sont coalescées.

## Topics Robine Discovery

Le profil natif repose sur des topics réservés :

```text
robine/v1/discovery/<origin-id>/config
robine/v1/state/<origin-id>
robine/v1/availability/<origin-id>
robine/v1/command/<origin-id>
```

Le payload `config` inclut une version de schéma, un `origin_id` stable, les métadonnées d'appareil, les composants et leurs capacités. Le payload d'état est un document JSON limité, sans code exécutable. Les spécifications de schéma exactes sont publiées avec `robine-api-contract` avant l'implémentation du protocole.

## Découpage Rust

```text
robine-mqtt-contract       # schémas Robine Discovery et profils déclaratifs
robine-protocol-mqtt       # client MQTT, reconnexion, souscriptions et limitations
robine-mqtt-compat-ha      # import borné de Home Assistant Discovery, optionnel
```

`robine-mqtt-contract` ne dépend que de types purs. `robine-protocol-mqtt` appelle les ports entrants de l'application. `robine-mqtt-compat-ha` est un crate séparé afin que la compatibilité Home Assistant ne devienne pas le modèle canonique de Robine.

## Critères d'acceptation

- Un appareil Robine Discovery est découvert depuis un message retenu, retrouve le même identifiant après redémarrage et ne crée pas de doublon.
- Un message MQTT invalide, trop grand ou contenant une expression de template est rejeté sans modifier l'état courant.
- Une commande MQTT avec confirmation `:reported` n'est réussie qu'après un état compatible rapporté.
- La perte du broker rend uniquement les entités MQTT indisponibles ; Hue, l'API, Flow et le store restent disponibles.
- Un import Home Assistant compatible fonctionne sans parser YAML, Jinja ou code utilisateur.
- Le crate de domaine et l'application compilent sans client MQTT ni dépendance à un broker.
